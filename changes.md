- [Norman] feat: RustWarden 1.0.0, the first public release. Releases and updates come from this GitHub repo.
- [Norman] refactor: plugin registry (src/plugins/registry.rs). Database tables, workers, settings clean-up and Network sub-tabs of ha, thinkbroadband, ping, speedtest and opnsense now come from one list instead of being wired in by hand. First step of the Plugins / .wasm plugin system.
- [Norman] feat: Settings > Plugins replaces Integrations, with System Plugins and Notification Plugins sections. `.wasm` plugins (sandboxed with wasmtime, new `plugin-sdk` crate) run from `Program Files\RustWarden\plugins` after you approve the exact file and any opt-in permissions; each can add tabs and a settings page, has its own config, encrypted secrets and database tables, and can reach only the hosts it declares. Install from file, enable/disable and remove are on the page. The Prometheus metrics switch moved to Settings > General. Built-in integrations still use their old pages until they are ported.
- [Norman] feat: plugin SDK for authors (`plugin_sdk::guest`, `PLUGINS.md`, `plugins/example-hello`) and six notification services (Discord, Slack/Mattermost/Rocket.Chat, Pushbullet, ntfy, Gotify, generic webhook) built as `.wasm` plugins under `plugins/`. They receive every alert once the user approves the "alerts.read" permission and can post only to the hosts they declare ("*" for self-hosted servers, shown in the approval dialog). The built-in notification pages stay until the plugin files ship with releases; having both on would send each alert twice.
- [Norman] feat: the first-party plugins are built into RustWarden.exe (built by build.rs for wasm32-wasip1, so the release workflows install that target) and load from memory: no files to extract, they update with the app, need no administrator rights and are trusted like the exe itself. Settings > Plugins lists them with a switch each. Old settings are carried over on the first start: the six notification services' addresses and tokens (now secrets of their plugin) and the ping hosts, layout and stored history. Ping Monitor is now a plugin (the host pings for it with the new `ping` permission; its tab uses the same charts as before, drawn by RustWarden from the plugin's own tables). The Network settings page no longer has a Ping tab switch: turn the plugin on under Settings > Plugins.
- [Norman] feat: Home Assistant is now a built-in plugin. It uses the new `devices.annotate` permission: the host gives it the scanned devices, it looks each up in Home Assistant (one a second, hourly while unmatched, daily once matched) and stores the result in its own table, which the Scanner tab reads for the name, area, icon and link. The first Home Assistant from your old settings (address, token, name and type options) is carried over; the others in the list were never used and are dropped. HTTP requests from plugins now report a failing status as an error (`HTTP 401`). Plugins get WASI `random_get` only (hash maps need it); every other system import is still refused.
- [Norman] feat: VirusTotal is now a built-in plugin. The plugin holds the API key (an encrypted secret) and the auto-scan switch, and with the `programs.hash` permission RustWarden does the hashing, lookups and confirmed uploads as before, so the Firewall column and new-program popups work the same. Your old key and auto-scan setting are carried over. It is on when a key is saved; turning the plugin off turns every VirusTotal lookup off.
- [Norman] feat: OPNsense, Speedtest and thinkbroadband are plugins too, so every integration now lives on Settings > Plugins. OPNsense keeps its probe and its options gated on what the API key was shown to allow (the self-signed certificate option is a manifest flag the approval dialog shows). Speedtest uses the new `helper.exe` permission: RustWarden downloads Ookla's CLI from the address the plugin names, checks its SHA-256 and runs it; the dial, route map and history are drawn by RustWarden from the plugin's data, and Demo mode animates a made-up test. thinkbroadband uses `browser.session` (the same sign-in browser window as before) and `alerts.write` for packet-loss alerts. Your old settings and stored history are carried over, and so are settings from an older exported settings file when you import it. The Ping Monitor tab's Add host and Manage hosts buttons are back.
- [Norman] fix: Settings > Plugins rows no longer squash their text, a plugin can be switched on and its Settings opened before pressing Save (Cancel puts the switches back), and thinkbroadband downloads in smaller batches so the first download no longer traps. Plugin errors now show the real reason.

Each plugin has a Permissions button that opens a dialog, built-in plugins can be Uninstalled (after a confirmation with a "Remove Plugin Data" checkbox) and Restored from an "Uninstalled" list, and plugin settings dialogs sit on a card instead of being see-through. The Speedtest live graph is now one continuous graph like the traffic graph instead of split into download and upload halves.

- [Norman] feat: Settings > Countries & Network is split into Downloads, Geolocation and Lookups sub-tabs. Downloads has "Download all…", which first lists each database, its size, where it comes from and where it is saved, and how it is checked. Downloads now go to a temporary file and are only used if they open as a DB-IP database of the right kind (country, city or ASN) and hold data, so a bad download can't replace a good database.

It opens on a new install and once after the update that adds it; Skip setup is always available. A new install now starts with every alert off, so new users aren't flooded; existing installs keep their alerts. The "Playground" update channel is now called "Dev" (old settings still load), and on the Dev channel Settings > Other has a "Run wizard" button.

- [Norman] feat: Prometheus metrics is a built-in plugin (Settings > Plugins > Prometheus Metrics, port on its settings page) with a new `metrics.serve` permission, instead of a General setting. A setup that had metrics switched on keeps them on, on the same port. The endpoint also restarts after switching between Demo and Live.
- [Norman] feat: built-in UPnP Port Forwarding plugin (Network > Port Forwarding). New `upnp` plugin permission and a `Copy` button widget in the plugin SDK. It asks the router for a random public port leading to a port on this PC, lists the mappings with a "Copy address" button, and removes them again.
- [Norman] feat: built-in Cloudflare Tunnel plugin (Network > Cloudflare Tunnel) that downloads a pinned, checksum-verified `cloudflared` and runs a tunnel from a token, or after "Log in with Cloudflare". Plugin SDK additions: `helper_stop`, a helper whose download is a bare .exe, and a helper that runs until stopped (timeout 0) and streams its error output. Running helpers are stopped when RustWarden closes.
- [Norman] feat: "Block an app by clicking it" in the RustWarden menu and the tray menu: a + cursor over the screen tints the window under the mouse, and clicking it asks to block that program in both directions. New Backend method `block_program` (Live adds RustWarden's own rules, Demo only reports). A banner at the top says how to use it, and any window can be picked (Explorer included).
